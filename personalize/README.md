# 个人化微调

**仓库不含任何个人语料或个人权重，微调出的权重只留本机。** 本目录只提供方法，让每个人在自己的设备上复现。

## 为什么不把个人数据放进仓库

模型会记住少见或重复的内容，打分接口也能被用来推断某个词是否出现在训练数据里，脱敏不能保证安全。
因此公开发布的模型只用公开语料训练，个人语料、个人微调权重与选词统计只保存在本机用户目录，
不进入任何仓库（包括私有仓库，因为仓库可能改为公开）。

脚本与 `.gitignore` 从两方面保证这一点：

1. 语料路径和输出目录若位于本仓库目录内，脚本拒绝运行；输出默认写到 `~/.ime-personal/`。
2. `.gitignore` 排除 `select_corpus*`、`personalize/local/`、`.ime-personal/`，以及个人化输出的检查点与 GGUF。
   脚本不打印任何语料文字，日志和 `manifest.json` 里只有数量和指标。

## 输入

`select_corpus.tsv`（或其所在目录，分卷与 `.gz` 均可读取），制表符分隔，10 列：

| 列 | 含义 |
|---|---|
| 1 | id |
| 2 | 分钟时间戳 |
| 3 | 输入字母数 |
| 4 | 上文最后 6 字 |
| 5 | 所选词 |
| 6 | 最终首位 |
| 7 | 原首位 |
| 8 | 类型：`hard`（所选不是最终首位）或 `anchor`（选了首位的抽样） |
| 9 | 距上次上屏秒数 |
| 10 | 模型 |

revise 行表示用户选词后很快退格，该条目可能选错：同 id 的 revise 行（或 `revise<TAB>id`）出现时，
对应条目整体丢弃。

## 用法

```bash
python personalize/personalize.py \
    --corpus  <用户目录>/select_corpus.tsv \
    --base    <公开语料训练的 student_best.pt> \
    --public-eval <公开评测题 items_eval.jsonl>
```

可选参数：`--out`（输出目录）、`--epochs`（默认 5）、`--lr`（默认 3e-5）、`--batch`、`--device`。
依赖与主流水线相同（torch、numpy），导出 GGUF 需要 `gguf` 包，或设置环境变量 `GGUF_PY` 指向 llama.cpp 的 `gguf-py` 目录。

## 做了什么

1. 丢弃 revise 指向的条目。
2. hard 条目构造成对样本：（上文，所选词）为正例，（上文，最终首位）与（上文，原首位）为反例，用成对排序损失。
   anchor 条目作不变样本：所选词的得分保持与基础模型一致，防止遗忘。
3. 以基础学生模型为起点微调，另加语言模型交叉熵与对基础模型的 KL 两项正则。数据小，几分钟即可；
   每 50 步写一次检查点，中断后用同样的命令继续。
4. 验收（两条都要满足，否则放弃、不导出）：
   - 留出 10% 的个人 hard 样本，所选词排第一的比例必须高于基础模型；
   - 公开评测集（默认抽 3000 题）准确率相对基础模型下降不超过 1 个百分点。
5. 通过后导出 `student_personal.q8_0.gguf`（Q8_0 量化，约为 F32 的四分之一）与同名 `.vocab.txt`，
   并保存 `student_personal.pt` 与只含数字的 `manifest.json`。验收不过则写 `abandoned.json`，不导出。

hard 样本太少（留出不足 5 条）时脚本拒绝运行，先多积累一些再微调。

## 自测

```bash
python personalize/tests/selftest_personalize.py
```

自测只用合成数据（编造的字和词），不读取任何真实个人数据；覆盖解析、隐私守卫、微调、导出、续跑与放弃路径。

## 已知局限

- 验收默认阈值与正则权重按合成数据和基础模型的规模设定，真实个人数据上可能需要调整 `--lr`、`--w-kl`。
- Q8_0 导出与 F32 的对数概率相差约 0.25%，不影响候选排序，但不是逐位一致。
- 微调只改学生模型本身，不改词频融合与词对权重。
