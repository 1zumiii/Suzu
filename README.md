# Suzu：输入法候选排序小模型

Suzu 是一组只做一件事的小模型：给定上文和同一拼音下的若干候选词，对候选打分排序。
它由 Qwen3.5 作教师蒸馏而来，字符级词表（6000 字），Q8_0 量化后约 42 MB，手机 CPU 上约 20 ms 完成一次打分，
评测准确率与 Qwen3.5-0.8B 相当。训练只使用公开语料，不含任何个人数据。

## 模型

| 名称 | 目录 | 规模 | 说明 |
|---|---|---|---|
| Suzu-1 | `models/suzu-1` | 8 层、384 维、约 16.5M 参数 | 第一轮 |
| Suzu-2 | `models/suzu-2` | 12 层、512 维、约 40.9M 参数，Q8_0 约 41.9 MiB | 第二轮 |

模型目录和文件名与名称一致；训练过程中的中间文件（如 `ckpt/student_best.pt`）仍沿用 `student` 前缀。

## 评测结果

评测集为 16000 道题（上文 + 拼音，在同音候选中选出语料中真实出现的词），来自维基百科中文，易例与难例各半，按真实比例加权。指标为首选准确率，「混合」为模型分加词频先验。完整报告见 `reports/round2/report.md`。

| 系统 | 混合（自然加权） | 难例（纯模型） |
|---|---|---|
| 词频第一（近似 Rime 默认顺序） | 83.6%（纯模型） | 0.0% |
| 字符三元模型 | 87.2% | 43.5% |
| Qwen3.5-0.8B | 92.7% | 70.7% |
| Suzu-1 | 92.1% | 66.6% |
| **Suzu-2** | **92.8%** | **72.4%** |
| Qwen3.5-9B（教师） | 95.1% | 80.1% |

延迟：桌面 CPU 上 Suzu-2 在 2 线程下约 21 ms（8 个候选合成一批，前缀可后台预解码）；
Zenfone 10 上 2 线程、6 个候选、含进程间通信，中位 20.1 ms，守护进程常驻内存约 115 MB。详见 `reports/round2/latency.md`。

## 使用

模型为 GGUF（gpt2 架构），词表为单独的 `*.vocab.txt`（一行一个字符，行号即 token 编号：0 为填充，1 为未知，2 为句首）。
打分方式：输入为句首符加上文最后至多 30 个字再加候选的字；候选得分为各字对数概率之和。该模型不使用 llama.cpp 的分词器，需要推理端自行做字符到编号的映射。
`tools/student_check.cpp` 是核对数值的最小示例；完整的输入法集成（Rime 的 Lua 过滤器、推理核心补丁、安卓守护进程）见
[rime-ice-Custom](https://github.com/1zumiii/rime-ice-Custom)。

## 局限

- 语料是维基百科，偏书面语，只覆盖简体；评测反映的是书面上下文中的同音词消歧，不是日常聊天。
- 「混合」一列的先验权重 λ 在评测集上选取，数字略乐观，适合相对比较，不宜当作绝对指标。
- 学生是字符级词表，教师是子词词表，两者只在排序上对齐；词表之外的字按未知字处理。
- 延迟为实测的参考值，不同设备差异较大。
- 个人化（用自己的输入记录微调）只提供方法，见 `personalize/README.md`；个人语料和个人权重不应进入任何仓库。

## 复现流水线

先做阶段 0 的评测，用数字判断值不值得继续，再决定是否训练学生。流水线在 Windows（RTX 5070 12 GB）上后台无人值守运行，可随时停止，断点续跑。

| 阶段 | 内容 | 产物 |
|---|---|---|
| fetch | 下载维基百科中文分片，转简体，抽句子 | `sentences.txt` |
| build | 分词、标拼音，出题：上文 + 拼音 → 同音候选（按词频降序），答案取语料中真实出现的词 | `items_eval.jsonl`、`items_train.jsonl` |
| score_* | n-gram 基线、Qwen3.5 的 0.8B / 4B / 9B 各自给每道题的候选打分 | `scores/*.jsonl` |
| report0 | 汇总首选准确率，给出是否继续的判定 | `report_stage0.md`、`gates.json` |
| teacher_train | 教师给训练题打分（仅判定通过时执行） | `scores/<教师>__train.jsonl` |
| train | 训练约 16 M 参数的字符级学生：语言模型损失 + 候选排序的 KL | `ckpt/student_best.pt` |
| score_student、report_final | 学生在评测题上打分并出终稿 | `report.md` |

对照系统：词频第一（近似 Rime 默认顺序）、字符三元模型（文法模型基线）、三档 Qwen 模型。
指标为首选准确率，按评测句里易例与难例的真实比例加权；「混合」一列为模型分加词频先验，对应实际部署里的融合方式。

判定规则（阈值在 `s3_report.py` 顶部，可调）：

- 教师相对 0.8B 的混合准确率提升 ≥ 1.5 个百分点，或难例提升 ≥ 3 个百分点：说明有蒸馏空间。
- 0.8B 相对 n-gram 的混合准确率提升 ≥ 2 个百分点：说明大模型确有价值。
- 两条都满足才继续训练学生；否则停在阶段 0，结论改为裁剪词表等无需训练的方案。

## 使用

下载内容需事先确认：

- 维基百科中文第一分片约 590 MB。
- Qwen3.5-0.8B 约 1.6 GB，4B 约 9 GB，9B 约 19 GB（即使 4 位量化加载，仍需下载完整权重）。
- 数据目录建议预留 45 GB。只想省空间时，从 `models.json` 删掉 4B 一项。
- 网络不通时可设置环境变量 `HF_ENDPOINT` 指向镜像站。

```powershell
# 需要 Python 3.12 或 3.13（3.14+ 目前没有 torch cu128 轮子）；没有 py 启动器时：.\setup.ps1 -Python "路径\python.exe"
.\setup.ps1          # 建虚拟环境，装 CUDA 12.8 版 torch 和依赖，并预检
.\run.ps1 smoke      # 冒烟测试：小语料、仅 0.8B、学生训练 150 步，约 10~20 分钟，前台运行
.\run.ps1 start      # 正式运行，后台，关窗口、注销都不受影响
.\run.ps1 status     # 查看完成情况、当前进度、最近日志、显卡占用
.\run.ps1 stop       # 在当前批次存盘后停止
.\run.ps1 autostart  # 登记登录后自动续跑，重启、断电、系统更新后无需手动操作
```

建议先跑冒烟测试，确认 Qwen3.5 能加载、5070 的 torch 正常，再正式启动。

## 稳定性设计

- 每个阶段完成后留标记文件，重启后跳过；阶段内部断点续跑：
  打分阶段以追加方式写 JSONL，续跑时跳过已写出的题号，并截掉被掐断的半行；
  训练阶段每 1000 步原子写检查点，每步随机抽样只取决于步数，续跑后数据顺序与不中断时一致。
- `watchdog.ps1` 在进程异常退出时自动重启，退避间隔递增；运行超过 10 分钟再失败则重新计数；连续失败 30 次放弃。
- 同一阶段连续失败 4 次会被标记为失败并跳过，不阻塞后续阶段；排查后用 `.\run.ps1 retry` 清除标记再启动。
- 显存不足时自动减小批大小；运行期间阻止系统睡眠。
- 停止请求写入 `data\STOP`，只在批次边界响应；强制结束最多损失约 1 分钟进度。

## 已知风险

- Qwen3.5 为混合线性注意力的多模态架构，需要较新的 transformers（`qwen3_5` 架构）。
  线性注意力有两个加速内核：`flash-linear-attention`（纯 Python，依赖 Triton）和 `causal_conv1d`（需要编译）。
  未安装时 transformers 会退回慢速实现，结果正确但更慢。实测（Windows 11、RTX 5070、torch 2.11 + cu128）：
  `pip install triton-windows==3.7.1.post27 flash-linear-attention` 能装上并正常工作，`setup.ps1` 已包含这一步；
  打分速度 0.8B 从 85.8 提到 131.3 题/秒（+53%），4B(nf4) 从 28.3 提到 42.9 题/秒（+52%），首选与命中数不变。
  `causal_conv1d` 未安装（需要编译，未试），仍会有一条退回提示。`triton-windows` 的版本与 torch 版本配套，换 torch 版本时要对应调整。
- 4 位量化需要 bitsandbytes，Windows 版近年才稳定；加载失败时该阶段会被标记失败，其余结果仍会出报告。
- 模型仓库名按官方命名填写，未逐一实测加载，运行前可用 `python preflight.py` 核对。
- 语料为维基百科，偏书面语，与日常聊天有差距；评测结论主要反映「同音词在书面上下文中的消歧能力」。
- 学生与教师同口径（对候选取字符对数概率之和），但学生是字符级词表，教师是子词词表，两者只在排序上对齐。
- 参考延迟为本机 CPU 单线程粗测，手机端需另行实测。
- 本机（macOS）已用玩具语料和桩模块验证出题、n-gram、报告判定、停止与续跑无重复、阶段失败隔离；
  Qwen 加载、下载、学生训练部分需要在 Windows 上通过冒烟测试确认。
