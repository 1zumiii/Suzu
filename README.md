# Suzu：输入法候选排序小模型

Suzu 是一组只做一件事的小模型：给定上文和同一拼音下的若干候选词，对候选打分排序。它由 Qwen3.5 作教师蒸馏而来，字符级词表（6000 字），Q8_0 量化后约 44 MB（41.9 MiB），手机 CPU 上用输入法的推理核心打分，中位约 11 ms，评测准确率与 Qwen3.5-0.8B 相当。训练只使用公开语料、教师模型生成的合成句子和公开词库，不含任何个人数据。

## 模型

模型权重不放在这个仓库里，发布在 Hugging Face：当前版本 [IzumiThe3rd/Suzu-2.4](https://huggingface.co/IzumiThe3rd/Suzu-2.4)，更早的版本有 [Suzu-2.1](https://huggingface.co/IzumiThe3rd/Suzu-2.1) 和 [Suzu-2](https://huggingface.co/IzumiThe3rd/Suzu-2)（均为 GGUF，Q8_0，约 41.9 MiB，附词表）。

| 名称 | 规模 | 说明 |
|---|---|---|
| Suzu-1 | 8 层、384 维、约 16.5M 参数 | 第一轮，仅用于对比，不发布权重 |
| Suzu-2 | 12 层、512 维、约 40.9M 参数，Q8_0 约 41.9 MiB | 第二轮 |
| Suzu-2.1 | 与 Suzu-2 相同 | 第三轮，在 Suzu-2 权重上续训，补充日常口语、技术、二次元语料，已发布 |
| Suzu-2.2、Suzu-2.3 | 与 Suzu-2 相同 | 网络用语补训、单字专项，对照实验，未发布 |
| Suzu-2.4 | 与 Suzu-2 相同 | 第四轮，在 Suzu-2.1 权重上用 6 万道简拼题续训，已发布 |

训练过程中的中间文件（如 `ckpt/student_best.pt`）沿用 `student` 前缀。

## 评测结果

评测集为 16000 道题（上文 + 拼音，在同音候选中选出语料中真实出现的词），来自维基百科中文，易例与难例各半，按真实比例加权。指标为首选准确率，“混合”为模型分加词频先验。完整报告见 `reports/round2/report.md`。下表是 Suzu-2 的评测；Suzu-2.1 与 Suzu-2.4 相对前一版的对比见后面各节。

| 系统 | 混合（自然加权） | 难例（纯模型） |
|---|---|---|
| 词频第一（近似 Rime 默认顺序） | 83.6%（纯模型） | 0.0% |
| 字符三元模型 | 87.2% | 43.5% |
| Qwen3.5-0.8B | 92.7% | 70.7% |
| Suzu-1 | 92.1% | 66.6% |
| **Suzu-2** | **92.8%** | **72.4%** |
| Qwen3.5-9B（教师） | 95.1% | 80.1% |

延迟与内存：下面的数字是旧推理核心（2026-10-19 重写之前）测得的，保留作历史记录：桌面 CPU 上 Suzu-2 在 2 线程下约 21 ms，Zenfone 10 上中位 20.1 ms，守护进程常驻内存约 115 MB，详见 `reports/round2/latency.md`。新核心下手机打分中位约 11 ms，守护进程常驻内存约 61 MB（不含候选生成），见 [suzu-ime 的技术报告](https://github.com/1zumiii/suzu-ime/blob/main/docs/technical-report.md)。

## Suzu-2.4

Suzu-2.4 在 Suzu-2.1 的权重上续训，结构、词表和文件大小不变，补充了简拼训练：两字母简拼和首字全拼加次字首字母。两字母简拼 1300 题上首选由 44.6% 升到 51.2%（+6.6，区间 +4.7 到 +8.6），补上教师差距的约一半；全拼在种子波动内没有退步。在输入法的真实链路里，两字母简拼首选由 41.8% 升到 49.4%，混合输入由 68.7% 升到 72.5%。模型卡见 `MODEL_CARD_2.4.md`，训练与评测见 `reports/round5/abbrev_training.md`。

## Suzu-2.1

Suzu-2.1 在 Suzu-2 的权重上续训，结构、词表和文件大小不变，只补充了日常口语、技术和二次元三个领域的语料，使用方式与 Suzu-2 完全相同，可直接替换。模型卡见 `MODEL_CARD_2.1.md`。版本号规则：主版本只在结构、词表变化或从零训练时递增，同结构续训只递增次版本。训练设定与完整数据见 `reports/round3/suzu3_eval.md`。

### 与 Suzu-2 的对比

首选准确率，混合（模型分加词频先验），括号内为同题配对 95% 区间。新留出题与训练语料不重叠，未参与任何调参和检查点选择。

| 题集 | 题数 | Suzu-2 | Suzu-2.1 | 差 |
|---|---|---|---|---|
| 维基评测 | 16000 | 83.6% | 84.1% | +0.5（±0.3） |
| 技术（新留出） | 220 | 80.0% | 94.5% | +14.5（±5.2） |
| 二次元（新留出） | 193 | 78.2% | 90.7% | +12.4（±5.1） |
| 日常口语（新留出） | 221 | 81.4% | 95.5% | +14.0（±4.9） |

难例提升最大：日常口语难例 62.1% 到 89.7%，技术难例 67.8% 到 87.8%，二次元难例 61.7% 到 85.2%。

| 指标 | Suzu-2 | Suzu-2.1 |
|---|---|---|
| 桌面 CPU 前缀（7 线程，可后台预解码） | 11.3 ms | 11.3 ms |
| 桌面 CPU 候选批（关键路径） | 9.6 ms | 9.5 ms |
| Zenfone 10 打分中位（2 线程，6 个候选，含进程间通信） | 20.5 ms、19.5 ms | 19.3 ms、19.1 ms |
| Zenfone 10 常驻内存（VmRSS） | 约 116 MB | 约 116 MB |
| Q8_0 体积 | 43.9 MB | 43.9 MB |

以上延迟与内存为旧推理核心下交替运行两轮的实测，Suzu-2 与 Suzu-2.1 无差别；新核心的数字见上文的链接。

### 注意事项

- 对试点二（13.4 万题的续训）在新留出题上只多 0.5 到 1.4 个百分点，均在区间内。放量的收益主要是结果更稳，不是准确率再上一个台阶。
- 领域题为合成句子，每题集约 200 题，区间约 ±5 个百分点，只能判断量级。新留出题里后加的一批难词取自训练语料词表，可能略有利于 Suzu-2.1。
- 手机上的 6 条同音词冒烟用例，两个模型都是 5/6，错的题不同，样本过小，不构成结论。
- 在 Mac 上另做了独立核对：用同样的句子，但候选取 rime-ice 词库里同拼音同长度权重最高的 4 个词，纯模型首选准确率 1325 题，Suzu-2 为 81.2%，Suzu-2.1 为 93.0%，差 +11.8（95% 区间 +10.0 到 +13.8），各领域区间均不含 0。题目仍是同一批手写句子，对 Suzu-2.1 可能略有利。
- Suzu-2.1 是续训，不是从零训练。续训是否已经饱和，需要一次从零训练的对照。

### 后续计划

1. 用真实文本验证：用不由合成语料生成的真实文本复核领域提升，等待数据。
2. 简拼继续加量的边际收益很小（6 万题只比 2.4 万题多约 1 个点），再往上要换思路，例如让学生更多地学教师的排序，而不是加题。
3. 网络用语专项补训（Suzu-2.2）：对训练过的词压下去率由 24% 降到约 5%，对没见过的词几乎没有泛化，未发布，报告见 `reports/round4`。网络用语的问题主要靠输入法词库的权重解决。
4. 容量对照与从零训练的对照：暂不进行，当前不改结构。
5. 个人化：只提供方法，个人语料和个人权重不入库。

## 使用模型

模型为 GGUF（gpt2 架构），词表为单独的 `*.vocab.txt`（一行一个字符，行号即 token 编号：0 为填充，1 为未知，2 为句首）。打分方式：输入为句首符加上文最后至多 30 个字再加候选的字；候选得分为各字对数概率之和。Suzu 不使用 llama.cpp 的分词器，需要推理端自行做字符到编号的映射。`tools/student_check.cpp` 是核对数值的最小示例；完整的输入法集成（推理核心、Rime 的 Lua 过滤器、macOS、Windows 与 Android 三端接入、安卓守护进程）见 [suzu-ime](https://github.com/1zumiii/suzu-ime)，雾凇拼音的词库与配置见 [rime-ice-Custom](https://github.com/1zumiii/rime-ice-Custom)。

## 局限

- 语料是维基百科，偏书面语，只覆盖简体；评测反映的是书面上下文中的同音词消歧，不是日常聊天。
- “混合”一列的先验权重 λ 在评测集上选取，数字略乐观，适合相对比较，不宜当作绝对指标。
- 学生是字符级词表，教师是子词词表，两者只在排序上对齐；词表之外的字按未知字处理。
- 延迟为实测的参考值，不同设备差异较大。
- 个人化（用自己的输入记录微调）只提供方法，见 `personalize/README.md`；个人语料和个人权重不应进入任何仓库。

## 复现 pipeline

先做阶段 0 的评测，用数字判断值不值得继续，再决定是否训练学生。pipeline 在 Windows（RTX 5070 12 GB）上后台无人值守运行，可随时停止，断点续跑。

| 阶段 | 内容 | 产物 |
|---|---|---|
| fetch | 下载维基百科中文分片，转简体，抽句子 | `sentences.txt` |
| build | 分词、标拼音，出题：上文 + 拼音 → 同音候选（按词频降序），答案取语料中真实出现的词 | `items_eval.jsonl`、`items_train.jsonl` |
| score_* | n-gram 基线、Qwen3.5 的 0.8B / 4B / 9B 各自给每道题的候选打分 | `scores/*.jsonl` |
| report0 | 汇总首选准确率，给出是否继续的判定 | `report_stage0.md`、`gates.json` |
| teacher_train | 教师给训练题打分（仅判定通过时执行） | `scores/<教师>__train.jsonl` |
| train | 训练字符级学生（当前约 40.9 M 参数，Suzu-1 为 16.5 M）：语言模型损失 + 候选排序的 KL | `ckpt/student_best.pt` |
| score_student、report_final | 学生在评测题上打分并出终稿 | `report.md` |

对照系统：词频第一（近似 Rime 默认顺序）、字符三元模型（文法模型基线）、三档 Qwen 模型。指标为首选准确率，按评测句里易例与难例的真实比例加权；“混合”一列为模型分加词频先验，对应实际部署里的融合方式。

判定规则（阈值在 `pipeline/s3_report.py` 顶部，可调）：

- 教师相对 0.8B 的混合准确率提升 ≥ 1.5 个百分点，或难例提升 ≥ 3 个百分点：说明有蒸馏空间。
- 0.8B 相对 n-gram 的混合准确率提升 ≥ 2 个百分点：说明大模型确有价值。
- 两条都满足才继续训练学生；否则停在阶段 0，结论改为裁剪词表等无需训练的方案。

## 运行 pipeline

`tools/run_r3_*.ps1` 与 `reports/` 里的路径（`C:\Users\…\work`、`D:\distill-data-*`、`E:\Suzu-data`）是训练机上的数据与构建目录，属于复现记录。在别的机器上运行须改成本机路径；评测用的词库目录用环境变量 `CN_DICTS` 指定（rime-suzu 的词库包安装后的 `cn_dicts`）。


下载内容需事先确认：

- 维基百科中文第一分片约 590 MB。
- Qwen3.5-0.8B 约 1.6 GB，4B 约 9 GB，9B 约 19 GB（即使 4 位量化加载，仍需下载完整权重）。
- 数据目录建议预留 45 GB。只想省空间时，从 `models.json` 删掉 4B 一项。
- 网络不通时可设置环境变量 `HF_ENDPOINT` 指向镜像站。

```powershell
# 需要 Python 3.12 或 3.13（3.14+ 目前没有 torch cu128 轮子）；没有 py 启动器时：.\setup.ps1 -Python "路径\python.exe"
.\setup.ps1          # 建虚拟环境，装 CUDA 12.8 版 torch 和依赖，并预检
.\run.ps1 smoke      # 冒烟测试：小语料、仅 0.8B、学生训练 150 步，约 10~20 分钟，前台运行
.\run.ps1 start      # 正式运行，后台，关窗口、注销都不受影响
.\run.ps1 status     # 查看完成情况、当前进度、最近日志、显卡占用
.\run.ps1 stop       # 在当前批次存盘后停止
.\run.ps1 autostart  # 登记登录后自动续跑，重启、断电、系统更新后无需手动操作
```

建议先跑冒烟测试，确认 Qwen3.5 能加载、5070 的 torch 正常，再正式启动。

## 稳定性设计

- 每个阶段完成后留标记文件，重启后跳过。
- 打分阶段以追加方式写 JSONL，续跑时跳过已写出的题号，并截掉被中断而不完整的最后一行。
- 训练阶段每 1000 步原子写检查点。每步的随机抽样只取决于步数，续跑后的数据顺序与不中断时一致。
- `watchdog.ps1` 在进程异常退出时自动重启，退避间隔递增；运行超过 10 分钟再失败则重新计数；连续失败 30 次放弃。
- 同一阶段连续失败 4 次会被标记为失败并跳过，不阻塞后续阶段；排查后用 `.\run.ps1 retry` 清除标记再启动。
- 显存不足时自动减小批大小；运行期间阻止系统睡眠。
- 停止请求写入 `data\STOP`，只在批次边界响应；强制结束最多损失约 1 分钟进度。

## 已知风险

- Qwen3.5 为混合线性注意力的多模态架构，需要较新的 transformers（`qwen3_5` 架构）。
- 线性注意力有两个加速内核：`flash-linear-attention`（纯 Python，依赖 Triton）和 `causal_conv1d`（需要编译）。未安装时，transformers 退回慢速实现，结果正确，但更慢。
- Windows 上实测（Windows 11、RTX 5070、torch 2.11 + cu128）：`pip install triton-windows==3.7.1.post27 flash-linear-attention` 可以装上并正常工作，`setup.ps1` 已包含这一步。打分速度 0.8B 从 85.8 提到 131.3 题/秒（+53%），4B（nf4）从 28.3 提到 42.9 题/秒（+52%），首选与命中数不变。
- `causal_conv1d` 需要编译，未尝试安装，运行时仍有一条退回提示。`triton-windows` 的版本与 torch 版本配套，换 torch 版本时须对应调整。
- 4 位量化需要 bitsandbytes，Windows 版近年才稳定；加载失败时该阶段会被标记失败，其余结果仍会出报告。
- 模型仓库名按官方命名填写，未逐一实测加载，运行前可用 `python pipeline\preflight.py` 核对。
- 语料为维基百科，偏书面语，与日常聊天有差距；评测结论主要反映“同音词在书面上下文中的消歧能力”。
- 学生与教师同口径（对候选取字符对数概率之和），但学生是字符级词表，教师是子词词表，两者只在排序上对齐。
- pipeline 里的参考延迟为 CPU 单线程粗测，手机端需另行实测。
- 开发时在 macOS 上用玩具语料和桩模块验证了出题、n-gram、报告判定、停止与续跑无重复、阶段失败隔离。Qwen 加载、下载和学生训练部分，需要在 Windows 上通过冒烟测试确认。

## 目录

- `pipeline/`：Python 代码。`common.py` 公共设施，`s0_fetch.py` 到 `s4_train.py` 各阶段，`student_model.py` 学生模型，`pipeline.py` 总控，`preflight.py` 预检，`export_gguf.py` 导出 GGUF。
- 根目录：`setup.ps1`、`run.ps1`、`run_round2.ps1`、`watchdog.ps1` 启停与守护脚本，`models.json` 模型清单，`requirements.txt`。
- `tests/`：自测（`tests/selftest.py` 无需 GPU）。`tools/`：数值核对、教师评测、各轮续训与评测脚本（`run_r3_*.ps1` 为第三轮领域语料；第四轮及之后的各步骤是 `r4_*.py`、`t_*.py`、`g_*.py`、`frost_eval.py`，由训练机上的驱动脚本串联运行，驱动脚本含本机路径，未收录）。`personalize/`：个人化微调。模型权重在 Hugging Face。`reports/`：评测报告。
